# Конфигурация

Публичный файл конфигурации — `config.yaml`, проверяется по
[`contracts/config.schema.json`](../contracts/config.schema.json). Полный пример —
[`contracts/config.example.yaml`](../contracts/config.example.yaml). **Секретов в этом файле
нет** — токен бота, ключи сборщиков и токены пробников лежат отдельными файлами с правами
`0600` (см. [privacy.md](privacy.md)).

Ошибка валидации называет путь в JSON и нарушенное правило; сервис не стартует на невалидном
файле. После изменения файла нужен перезапуск API и сборщика.

[English version](configuration.md)

## `version`

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `version` | const `1` | — | версия схемы файла |

## `app`

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `default_language` | `ru` \| `en` | — | язык до того, как известен язык Telegram пользователя |
| `languages` | список `ru` \| `en` | — | включённые языки; переключатель показывает только их |
| `timezone` | имя IANA | `UTC` | группировка событий и срок заметки |
| `admin_contact_url` | `https://t.me/…` | — | куда ведёт кнопка «Написать администратору»; без поля кнопки нет |
| `public_url` | `https://…` | — | где открывается Mini App (`https://<домен>/app/mvp.html`); сюда ведёт кнопка бота на `/start` |

## `storage` (необязательно)

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `database` | путь | `./vpnpulse.sqlite3` | файл SQLite, общий для API и `vpn-pulse run`; создаёт `vpn-pulse init` |

## `telegram` (необязательно)

Без этого блока `vpn-pulse run` печатает сообщения, которые отправил бы, вместо доставки.

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `bot_token_file` | путь | — | файл `0600` с токеном бота; сам токен в `config.yaml` не хранится никогда |
| `group_chat_id` | строка или число | — | чат участников: подтверждённые сбои и восстановления |
| `admin_chat_id` | строка или число | группа | неподтверждённые проблемы и разрывы данных, без звука |

## `servers[]`

Может быть **пустым** сразу после установки — интерфейс покажет «Мониторинг настраивается»,
администратор увидит следующую команду.

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `id` | `^[a-z][a-z0-9-]{1,63}$` | — | публичный id в API и аналитике; никогда не hostname |
| `type` | `awg-host` \| `awg-docker` \| `hiddify` | — | какой helper-сборщик используется |
| `name.ru`, `name.en` | 1–80 символов | — | имена для участников |
| `country_code` | ISO 3166-1 alpha-2 | — | флаг и название страны |
| `enabled` | boolean | — | выключенные серверы не опрашиваются и не показываются |
| `recommended_priority` | целое ≥ 0 | `0` | приоритет среди одинаково подтверждённых; меньше — выше |
| `collector_ref` | строка | — | ссылка на файл учётных данных сборщика (не сами данные) |

## `monitoring`

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `collection_interval_seconds` | 30–3600 | `60` | как часто сборщик опрашивает сервер |
| `pc_target_interval_seconds` | 60–3600 | `60` | как часто PC-пробник проверяет каждую цель |
| `probe_deadline_seconds` | 5–120 | `20` | бюджет одной полной проверки |
| `confirmations` | 2–5 | `2` | сколько подряд результатов меняют публичное состояние |
| `freshness_seconds` | 60–3600 | `180` | свидетельства старше не подтверждают «работает» |

## `retention`

| Поле | Тип | По умолчанию | Примечание |
|---|---|---|---|
| `observations_days` | 1–30 | `7` | сырые свидетельства |
| `aggregates_days` | 7–365 | `90` | ряды доступности и подключений |
| `events_days` | 30–730 | `180` | события для участников |
| `analytics_raw_days` | 1–90 | `30` | продуктовая аналитика до агрегации |
| `audit_days` | 30–730 | `365` | действия администратора |

Пример — в английской версии и в `contracts/config.example.yaml`.
